# Design Spec: REQ-AI-002 — DefectPredictor 激活 dependency + staleness 因子

| 属性 | 内容 |
|------|------|
| **日期** | 2026-07-22 |
| **需求** | REQ-AI-002 |
| **方案** | A：归一化公式 + 权重重分配 |
| **影响文件** | `src/defect_predictor/predictor.py`, `tests/test_defect_predictor/test_defect_predictor.py` |

---

## 1. 背景

`ModuleMetrics` 已有 `dependency_count` 和 `last_modified_days` 两个字段，但 `_calculate_factors()` 从未使用它们。评分模型只有 5 个因子，忽略了依赖耦合度和代码陈旧度这两个重要风险信号。

---

## 2. 方案对比

| 方案 | 方法 | 优点 | 缺点 |
|------|------|------|------|
| **A（选中）** | 归一化公式 + 重分配权重 | 无需新依赖，改动最小 | 权重分配靠经验 |
| B | ML 回归模型学权重 | 数据驱动更精确 | 需标注数据，超出 scope |
| C | 独立风险子评分 | 可插拔 | 复杂度提升，与现有架构不一致 |

---

## 3. 因子设计

| 因子 | 归一化公式 | 满分条件 | 权重 |
|------|-----------|---------|------|
| dependency | `min(100, count × 5)` | 20 个依赖 | 7% |
| staleness | `min(100, days / 3.65)` | 365 天未修改 | 5% |

原有权重同步下调（总和保持 1.0）：

| 因子 | 旧权重 | 新权重 | 调整量 |
|------|--------|--------|--------|
| complexity | 25% | 22% | -3% |
| churn | 25% | 22% | -3% |
| coverage_gap | 20% | 18% | -2% |
| bug_history | 20% | 18% | -2% |
| size | 10% | 8% | -2% |
| dependency | — | 7% | +7% |
| staleness | — | 5% | +5% |

---

## 4. 接口变更

```python
# 新增：RISK_WEIGHTS 常量更新
RISK_WEIGHTS = {
    "complexity": 0.22, "churn": 0.22, "coverage_gap": 0.18,
    "bug_history": 0.18, "size": 0.08,
    "dependency": 0.07, "staleness": 0.05,  # NEW
}

# 新增：_calculate_factors 增加两个因子
factors["dependency"] = min(100.0, metrics.dependency_count * 5.0)
factors["staleness"] = min(100.0, metrics.last_modified_days / 3.65)

# 新增：recommendations 增加对应建议
if factors["dependency"] > 50: ...
if factors["staleness"] > 50: ...
```

`model_version` 更新为 `"rule-based-v1.1"`。

---

## 5. 测试策略

| 测试 | 场景 | 断言 |
|------|------|------|
| TC-PRD-003（更新） | factor keys 包含 dependency 和 staleness | 7 个 key 均存在 |
| TC-PRD-013（新增） | model_version 正确 | `== "rule-based-v1.1"` |
| TC-PRD-014（新增） | 依赖数影响风险分 | dep=20 比 dep=0 高 ≥ 5 分 |
| TC-PRD-015（新增） | 陈旧度影响风险分 | days=365 比 days=0 高 ≥ 4 分 |

所有原有 13 个测试必须仍 PASS。
