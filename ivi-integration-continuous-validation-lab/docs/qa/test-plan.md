# IVI 软件集成与持续验证实验室 — 测试计划

## 测试分层

| 层级 | 验证内容 | 运行时机 |
|---|---|---|
| Unit | manifest 校验、状态转换、回滚策略、门禁判定、指标计算 | 每次 `make ci` |
| Smoke | 合法样例包在 virtual 目标部署并执行关键健康检查 | 每次 CI |
| Integration | 包校验→部署→目标执行→证据→报告→门禁端到端链路 | PR / 本地完整入口 |
| Regression | 已登记缺陷对应的确定性回归场景 | PR / 发布候选 |
| Resilience | 注入部署、回滚、测试、报告失败并检查失败证据和退出码 | 隔离的验证 job 或手动运行 |

## 验收用例

| 用例 ID | 场景 | 核心断言 |
|---|---|---|
| TC-PKG-001 | 固定输入构建合成包 | 输出 manifest/hash；相同输入生成相同包内容 |
| TC-PKG-002 | 合法模拟包校验 | manifest/hash 校验成功并进入部署 |
| TC-PKG-003 | 缺字段或 hash 不匹配 | 拒绝部署，错误分类和日志可见 |
| TC-DEP-001 | 指定目标部署成功 | 目标版本切换并进入 `COMMITTED` |
| TC-DEP-002 | stage/verify 失败 | 仅指定目标触发回滚，旧版本恢复，门禁非零 |
| TC-DEP-003 | 回滚失败 | 指定目标标记 `ROLLBACK_FAILED`，同时保留原始部署错误，门禁非零 |
| TC-TGT-001 | virtual 与 bench-sim 执行同一契约 | 输出包含正确目标标识；不进行真实设备访问 |
| TC-LAY-001 | 单独选择 smoke/integration/regression | 只执行指定层级且结果汇总正确 |
| TC-EVD-001 | 测试失败 | run ID、阶段、分类、日志和测试结果互相关联 |
| TC-REP-001 | 正常报告生成 | HTML 和 JUnit XML 存在且可解析 |
| TC-REP-002 | 报告生成失败 | 门禁返回非零，不将运行标为成功 |
| TC-GATE-001 | 任一强制检查失败 | `make ci` 返回非零 |
| TC-GATE-002 | 全部强制检查成功 | `make ci` 返回零且产生证据 |
| TC-DEF-001 | 缺陷登记并修复 | 缺陷有分类/根因摘要/回归用例，回归选择可执行该用例 |
| TC-MET-001 | 串行与并行基准采集 | 输出可比较 elapsed time、worker 配置和样本信息 |
| TC-MET-002 | 重复运行稳定性统计 | 禁用 retry；只有实际执行后 pass/fail 的结果有效；skip、未启动和环境中断被排除并计数；至少 3 次有效结果才进入分母 |
| TC-MET-003 | 注入故障门禁校验 | 故障拒绝率和正常构建误拒绝率可从原始结果复算 |

## 指标计算与报告约束

- **回归耗时：** 以同一固定用例集合、环境和输入分别记录串行/并行 wall-clock 时间；记录 worker 数、预热方式和重复次数。
- **Flaky rate：** 对固定输入、目标和配置至少运行 3 次，计算时禁用 retry，每次计划运行最多有一个结果。测试实际执行并以 pass/fail 结束才是有效结果；skip/deselect、收集失败、测试未启动和环境中断均排除，环境中断的该次重复无效。至少有 3 次有效结果的用例才进入分母；同一用例出现 pass 与 fail 即计为 flaky，每个用例最多计一次。报告 flaky 用例数、有效用例数、排除结果数、计划运行数和窗口。
- **报告成功率：** 有效 HTML 报告运行数除以总运行数；无效/缺失报告均算失败。
- **故障识别率：** 被门禁拒绝的注入故障数除以注入故障总数；同时记录正常样本误拒绝率。注入验证应在隔离 job 中检查预期非零结果，不可掩盖真正的 CI 失败。

覆盖目标在实现阶段根据模块和风险确定；质量门禁最低要求是上述关键失败路径均有自动化验证。
