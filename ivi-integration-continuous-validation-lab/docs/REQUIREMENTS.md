# IVI 软件集成与持续验证实验室 — 需求

**来源：** [Issue #837](https://github.com/zhoujuxi2028/michael-zhou-qa-portfolio/issues/837)  
**状态：** 需求评审稿；所有目标均限于模拟实验室。

## 目标用户与故事

- **QA 工程师：** 希望对模拟 IVI/Cluster 软件包执行可重复的分层回归，以便在集成阶段尽早发现故障。
- **集成工程师：** 希望模拟部署失败、故障证据收集和回滚，以便验证异常路径而不接触真实设备。
- **项目维护者：** 希望本地与 CI 运行相同质量门禁，并获得报告和指标，以便比较回归效率与稳定性。
- **缺陷分析人员：** 希望从失败记录追溯根因分类、修复和新增回归用例，以便形成闭环。

## 功能需求

| ID | 需求 | 验收标准（实现时验证） |
|---|---|---|
| IVI-REQ-01 | 构建合成 IVI/Cluster 软件包 | 从仓库内固定输入生成带标识、版本和 hash 的模拟包；相同输入构建内容可复现，不生成真实固件 |
| IVI-REQ-02 | 校验软件包元数据与完整性 | 校验包标识、版本和 hash；错误/损坏包被拒绝并给出可读原因 |
| IVI-REQ-03 | 提供 virtual device 与 bench 两种模拟执行目标 | 同一测试契约可运行于两种目标；结果标识目标类型，bench 明确声明为模拟 |
| IVI-REQ-04 | 模拟定向部署/刷写状态流程 | 部署请求指定目标 ID；每个目标独立维护部署版本；可注入失败，状态和原因可追溯，不执行真实刷写 |
| IVI-REQ-05 | 部署失败时针对目标执行回滚 | 按目标保留部署前版本；失败后该目标恢复原版本，回滚失败也需记录并阻止门禁通过 |
| IVI-REQ-06 | 支持 smoke、integration、regression 分层 | 可单独选择层级；回归套件包含已登记缺陷对应的用例 |
| IVI-REQ-07 | 收集日志、测试证据和报告 | 每次运行有唯一 run ID、结果摘要、日志和 HTML 报告；报告生成失败应使 CI 失败 |
| IVI-REQ-08 | 建立缺陷到回归闭环 | 缺陷记录包含分类、根因摘要和关联用例；修复后的用例可在后续回归中执行 |
| IVI-REQ-09 | 提供统一质量门禁 | 任一必需测试失败、部署/回滚异常或报告缺失时，退出状态非零 |
| IVI-REQ-10 | 本地一键执行 | `make ci` 顺序运行项目必需检查并返回准确退出状态 |
| IVI-REQ-11 | 提供可复现运行环境及 CI 示例 | 本地和 Docker 可执行同一入口；CI 有正常通过路径及隔离的故障注入/门禁验证示例 |

## 非功能需求与指标

| ID | 需求 | 验收方式 |
|---|---|---|
| IVI-NFR-01 | 可重复性 | 固定样例输入重复运行得到相同功能结果；时间和 run ID 等波动字段不参与结果等同性比较 |
| IVI-NFR-02 | 可观测性 | 失败记录含阶段、目标、错误分类和日志定位信息 |
| IVI-NFR-03 | 安全边界 | 所有部署目标为本地模拟器；不含真实固件、凭证或真实硬件操作 |
| IVI-MET-01 | 基线与并行回归耗时 | 在固定样例套件上分别测量串行/并行 elapsed time，保留原始值与运行配置 |
| IVI-MET-02 | 稳定性 / flaky rate | 对固定输入和配置至少重复运行 3 次；一个用例的通过/失败状态在这些运行间不一致时计为 flaky。有效结果仅指测试实际执行并以 pass 或 fail 结束；skip/deselect、收集失败、测试未启动及环境中断不计入，环境中断使该次重复无效；统计时禁用 retry，仅计每次计划运行的首次执行。按用例统计：`flaky 用例数 / 至少有 3 次有效结果的用例数`，同时报告分子、分母、排除数、重复运行总数和窗口 |
| IVI-MET-03 | 报告生成成功率 | `成功生成有效报告的运行次数 / 总运行次数` |
| IVI-MET-04 | 故障构建识别率 | `被门禁正确拒绝的注入故障运行数 / 注入故障运行总数`；正常构建误拒绝率另行报告 |

## 范围与阶段

**首期范围：** 从固定输入构建合成样例包、virtual/bench 模拟目标、每目标独立部署状态机与回滚、分层测试、结构化日志、HTML 报告、质量门禁、指标采集、本地 `make ci`、Docker 和 GitHub Actions。

**不在范围内：** 实车/真实 ECU 或厂商平台接入、真实固件构建/签名/刷写、车规安全认证、声称符合量产流程、云端设备农场、生产级硬件在环系统。

**建议阶段：**
1. 最小闭环：包校验、虚拟目标、部署/回滚状态机、smoke 测试。
2. 回归与证据：集成/回归层、日志、HTML 报告、缺陷到回归映射。
3. 并行与交付：性能/稳定性指标、Docker、CI 成功与故障注入示例。

阶段顺序及每阶段范围须在设计评审中确认。
