# Vibe Testing Demo — 测试计划

## 测试类型

| 类型 | 目的 | 运行位置 |
|------|------|---------|
| 生成用例（E2E） | 意图 → 用例在 v1 上全部通过 | 本地 + CI |
| 变异验证 | 用例能发现注入缺陷，证明断言有效（VT-10） | 本地 + CI |
| 自愈验证 | v2 改版后修复成功且断言未削弱（VT-07） | 本地（需 AI），结果入库 |
| 断言守卫 | `check-assertions.mjs` 自身的单元测试（能识别删除 / 改弱断言） | 本地 + CI |

## 意图与用例

| 意图 | 内容 | 用例 | v1 | mutant |
|------|------|------|----|--------|
| VT-INT-01 | 正确账号登录成功，显示欢迎语 | TC-VT-01 | 通过 | 通过 |
| VT-INT-02 | 错误密码显示错误提示 | TC-VT-02 | 通过 | 通过 |
| VT-INT-03 | 连续 3 次失败后账号锁定，正确密码也无法登录 | TC-VT-03 | 通过 | **失败**（阈值 5） |
| VT-INT-04 | 新增待办出现在列表中 | TC-VT-04 | 通过 | 通过 |
| VT-INT-05 | 勾选待办后标记为完成 | TC-VT-05 | 通过 | 通过 |
| VT-INT-06 | 删除待办后从列表移除 | TC-VT-06 | 通过 | 通过 |
| VT-INT-07 | 空输入不能新增待办 | TC-VT-07 | 通过 | 通过 |

## 断言守卫用例

| 用例 | 场景 | 预期 |
|------|------|------|
| TC-AG-01 | 断言不变，只改选择器 | 通过 |
| TC-AG-02 | 删除一个 `expect` | 退出码 1 |
| TC-AG-03 | `toHaveText('Account locked')` 改为 `toBeVisible()` | 退出码 1 |
| TC-AG-04 | 期望值改动（`'Account locked'` → `''`） | 退出码 1 |

## 验收阈值

| 指标 | 阈值 |
|------|------|
| v1 上生成用例通过率 | 7 / 7 |
| mutant 上 TC-VT-03 | 必须失败 |
| v2 自愈 | 至少 1 次"失败 → 修复 → 通过"完整记录 |
| 断言守卫 | TC-AG-01 ~ 04 全部符合预期；自愈 diff 中被削弱的断言数 = 0 |
| CI | 不调用 AI，全程 < 5 分钟 |
