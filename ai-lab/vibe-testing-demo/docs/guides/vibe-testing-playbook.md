# Vibe Testing 落地规范

> **说明：** 本规范来自个人演示项目（#946）的实际运行，是推广建议，不代表已有团队落地经验（RSK-VT-005）。

## 流程

```text
意图（intents/）→ generate.sh → v1 上立即执行 → 人工复核 → 提交
页面改版 → 复制 v2 + 保存失败输出 → heal.sh → AST 守卫 + v2 执行 → 人工复核 diff → 提交
CI：只跑已提交用例 + 精确变异门禁 + 断言守卫，不调用 AI
```

## 提示词模板

### 意图

```markdown
# VT-INT-NN：<标题>

- 前置条件：<页面 / 数据状态>
- 操作：<步骤；写明所需的全部数据，如账号 `demo`、密码 `password`>
- 预期：<可观察结果，写出精确文案>
```

### 生成提示词要点（`prompts/generate.md`）

| 规则 | 来源（本项目实际问题） |
|------|----------------------|
| 只通过页面公开交互观察，不读实现 | 防止按实现写断言 |
| 意图写明全部测试数据 | VT-INT-03 缺密码，Agent 拒绝生成 |
| 用 `page` fixture 和相对 URL，由 `baseURL` 决定版本 | 首次生成写死主机端口 |
| 含子控件的元素不做整体精确文本断言 | VT-INT-04 缺陷（`Write testsDelete`） |
| 空容器不断言 `toBeVisible()` | VT-INT-07 缺陷 |
| matcher 参数使用静态字面量 | AST 守卫只能比较字面量 |
| Git 检查、复核由脚本和人完成，不写进 Agent 任务 | 与禁用的 read / shell 权限冲突，首次生成未写文件 |

### 自愈提示词要点（`prompts/heal.md`）

- 只改选择器和必要等待；不改 matcher、期望值、测试名和控制流
- 文件内容和失败输出由脚本注入，Agent 不读文件、不跑 shell

## 适用场景

| 适用 | 不适用 |
|------|--------|
| 意图清晰、结果可观察的 UI 流程（登录、表单、CRUD） | 需要复杂测试数据构造或后端状态准备 |
| 选择器频繁变化、维护成本高的回归用例 | 视觉回归、性能、安全测试 |
| 新功能的首批冒烟用例 | 断言依赖业务规则推导、意图本身不明确 |
| 演示 / 内部数据环境 | 含真实凭据或敏感数据的页面（RSK-VT-010） |

## 必备护栏

| 护栏 | 作用 | 本项目实现 |
|------|------|-----------|
| 生成后立即执行 | 发现 Agent 无法运行测试导致的缺陷 | `generate.sh` 之后 `npm test` |
| 精确变异门禁 | 证明断言能检出缺陷，且失败原因正确 | `scripts/check-mutant.mjs` |
| AST 断言守卫 | 自愈不能削弱断言 | `scripts/check-assertions.mjs` |
| 工具白名单 + Git 前后检查 | 限制写入范围（不等同进程隔离） | `--allow-tool`、`--deny-tool`、`git status` |
| 人工复核 | 守卫查不到的 helper、控制流、页面篡改 | [复核清单](../qa/ai-code-review-checklist.md) |
| CI 不调用 AI | 结果可复现 | `vibe-testing-ci.yml` |

## 推广路线图

| 阶段 | 目标 | 退出条件 |
|------|------|---------|
| 1 试点 | 1 个团队、1 个低风险模块、≤ 10 个意图 | 护栏全部启用；度量基线建立 |
| 2 规范 | 沉淀意图模板、提示词规则、复核清单 | 首次生成通过率 ≥ 70%；削弱断言 0 次漏检 |
| 3 推广 | 扩展到更多模块和团队；纳入 CI 门禁 | 复核耗时稳定；无因 AI 用例引起的误报事故 |
| 4 度量 | 定期复盘指标，迭代提示词 | 维护成本较手写基线下降 |

## 度量指标

| 指标 | 定义 | 本项目实测 |
|------|------|-----------|
| 首次生成通过率 | 提示词基线稳定后，首轮生成即在 v1 上通过的意图占比 | 4 / 7（03 意图缺数据未生成；04、07 断言缺陷） |
| 生成缺陷数 | 生成后执行发现的断言 / 选择器缺陷 | 2 |
| 自愈成功率 | 一次自愈后守卫通过且全部用例通过 | 1 / 1（7 个用例） |
| 断言削弱拦截率 | 削弱断言被守卫拦截的比例 | 1 / 1（CI 报红验证） |
| 变异检出 | 注入缺陷被目标用例检出 | 1 / 1（锁定阈值） |
| 复核耗时 | 每个用例的人工复核时间 | 待试点采集 |
| 单次生成成本 | AI Credits / 用例 | 约 0.4–3（Copilot CLI 输出） |
